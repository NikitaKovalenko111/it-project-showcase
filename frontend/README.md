## Запуск с API

```powershell
cd frontend
npm ci
npm run dev
```

По умолчанию используется настоящий API (`live`). Запросы идут на `/api/v1`,
Vite проксирует `/api` на `http://127.0.0.1:3005`. Настройки можно скопировать из
`.env.example` в `.env`. После изменения переменных перезапустите Vite.

- `VITE_API_MODE=live` — работа с бэком.
- `VITE_API_URL=/api/v1` — базовый путь API.
- `VITE_API_PROXY_TARGET=http://127.0.0.1:3005` — адрес сервера для Vite.
- `VITE_API_TIMEOUT_MS=15000` — таймаут запросов.

Если API доступен через существующий nginx на порту 3000, задайте
`VITE_API_PROXY_TARGET=http://127.0.0.1:3000`; Vite выберет свободный порт для фронта.
При `VITE_API_URL=/api/v1` запросы с того же адреса, что и интерфейс, идут
через фронтенд-прокси. Для запросов с других адресов прокси передаёт
`Origin` в API, и действует список разрешённых адресов на сервере.
В Docker фронт также собирается в режиме `live`, nginx отправляет `/api/` на `server:3005`.
После изменений исходников контейнер фронта нужно пересобрать.

## Демо

```powershell
npm run dev:mock
```

Режим mock включается явно. Демо-аккаунты и данные хранятся отдельно в браузере;
они не являются аккаунтами настоящего API. Для live зарегистрируйте пользователя
на сервере. Представителю компании и куратору требуется одобрение роли.

## API и проверки

Клиент преобразует серверные DTO в модели интерфейса в `src/api/backend.ts`.
Контракт сервера: [API](../backend/docs/API.md) и
[сценарии интеграции](../backend/docs/API_INTEGRATION_WORKFLOWS.md).
Списки используют серверную cursor/page pagination, защищённые запросы — Bearer
и обновление токенов. Ошибки live API не подменяются успешными mock-ответами.

```powershell
npm test
npm run build
```

Результаты текущей сверки и ограничения:
[отчёт об интеграции](../docs/frontend-backend-integration.md).
