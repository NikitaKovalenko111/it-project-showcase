# Просмотр последней версии фронтенда

Все функции, исправления QA и подготовленные моки собраны в обычной папке frontend основного проекта. Для запуска не нужны файлы из tmp или другой worktree.

## Через Docker

Из C:/hack/it-project-showcase:
    docker compose up --build frontend

Откройте http://localhost:3000. Сборка Docker по умолчанию использует VITE_API_MODE=mock. Если зависимые сервисы уже запущены, пересобрать только интерфейс можно командой:
    docker compose up -d --build --no-deps frontend

## Через npm

Из папки frontend, в PowerShell:
    npm ci
    $env:VITE_API_MODE = 'mock'
    npm run dev

Откройте адрес, напечатанный Vite. Если Docker уже занимает порт 3000, Vite предложит другой свободный порт.

## Данные и вход

Логины: student, company, curator, admin. Можно использовать кнопки выбора роли. Пароль в мок-режиме — любой непустой.

Подготовлены 37 вымышленных студентов, 13 компаний, 49 заданий, 15 проектов, 14 программ стажировок и практик, 39 заявок, 25 команд и 36 выполнений. Содержимое находится в src/api/fixtures; связанные данные собирают mockData.ts, competitionSeed.ts и showcaseSeed.ts.

Вложения хранятся в IndexedDB браузера, метаданные — в localStorage. Искусственного ограничения размера на фронтенде нет; доступное место зависит от браузера. Серверные ограничения описаны в docs/upload-size-contract.md.

Старые записи браузера не подмешиваются: используются ключи uust_showcase_curated_v1_ и showcase_curated_v1_. Последующие действия сохраняются локально. Для чистого показа используйте приватное окно.

## Что проверить

- Выбор и обрезку аватара в профиле.
- Стажировки и практики: публикацию, заявки и модерацию.
- Контрольные точки: создание, порядок и сроки.
- Команды, материалы решений, оценки и публикацию/отзыв итогов.
- Кабинет куратора, административные списки и пагинацию.
- Отступы, адаптивные таблицы и формы по исправлениям QA.

## Проверки и интеграция

    npm test
    npm run build

Режим работы с API сохранён; npm run dev:integration использует соответствующую конфигурацию. Неподдерживаемые API функции и требования к бэкенду описаны в docs/frontend-backend-gaps.md и docs/backend-api-handoff.md.

Перед объединением файлов сохранена резервная копия: tmp/frontend-before-consolidation.zip. Бэкенд, Dockerfile и docker-compose.yml не изменялись. В nginx.conf добавлено отложенное разрешение адреса API: мок-интерфейс запускается и при недоступном бэкенде.
