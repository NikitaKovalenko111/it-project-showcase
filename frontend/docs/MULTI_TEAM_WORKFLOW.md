# Участие и оценивание нескольких команд

В mock-режиме добавлены отдельные выполнения (`Execution`) с составом участников, своим результатом, файлами, статусом и оценкой. Результат одной команды больше не используется как результат всего мероприятия.

## Сценарии

- **Кейс и стажировка:** заявка проходит отбор организатором. После принятия появляется выполнение. Оценивание кейса сохраняет экспертные критерии из публикации: каждый до 10 баллов, с весами.
- **Хакатон:** капитан регистрирует подходящую по составу команду. Открытая регистрация сразу подтверждается, без отдельного одобрения организатором. Жюри проверяет отдельные решения по критериям публикации.
- **Олимпиада:** индивидуальная открытая регистрация. В форме публикации задаются задачи и максимум баллов каждой задачи, без экспертных критериев и весов. Организатор выставляет баллы за задачи, итог складывается из них. Автоматическая проверка исходного кода и выполнение программ не реализованы.

У организатора по умолчанию открывается общий список команд/участников: поиск, фильтры «В работе», «Сданные решения», «Оценённые решения», переход к работе. Студент видит только свои выполнения и общедоступные итоговые баллы. Состав команды содержит ссылки на профили.

Таблица результатов предварительная до публикации итогов. Организатор может завершить приём после проверки всех сданных работ. Участники без сдачи не входят в итоговый рейтинг, одинаковые баллы дают одинаковое место. Публикация итогов закрывает регистрацию и сдачу и фиксирует оценки.

Общий план и обсуждение проекта доступны отдельной кнопкой. В этом изменении результаты и оценки разделены по выполнениям; отдельные наборы контрольных точек и обсуждений каждого выполнения не вводились.

## Демо

В существующее mock-хранилище без удаления пользовательских записей добавляются:

- `/cases/demo_case/workspace` — обычный кейс с 12 командами;
- `/cases/demo_hackathon/workspace` — хакатон с 12 командами;
- `/cases/demo_olympiad/workspace` — олимпиада с 12 участниками.

В каждом примере: 4 оценённых работы, 5 сданных, 3 без сдачи. Работать со всеми решениями можно из демо-профиля компании «БашНефтеАвтоматика». Студент Алмаз представлен одним участием в каждом примере.

## Остальные правки

На главной всех ролей убрана пагинация. В каталогах она выровнена влево. При прокрутке вверх после 90 px движения появляется компактный поиск, а не вся панель фильтров; переход плавный. В исходной позиции остаются полные фильтры.

В разделе команд капитан сначала создаёт команду, затем выбирает её карточку и приглашает людей. Членство меняется после согласия адресата. В поиске по проекту отдельно находятся заявки на вступление, объявление набора в собственную команду и анкеты кандидатов. Дублированный заголовок поиска убран. Список проектов больше не содержит кнопки настроек; настройки внутри проекта свёрнуты в компактный блок.

## Интеграция и проверка

Новые операции временно используют существующий фронтендовый контракт `POST /community/<method>`: `getExecutions`, `submitExecution`, `gradeExecution`, `getLeaderboard`, `finalizeResults`. Модели: `types/execution.ts`, задачи олимпиады — `CaseProject.olympiadTasks`. Это не подтверждение наличия данных методов на бэкенде; live-ошибки не подменяются mock-ответами.

Проверки: production-сборка TypeScript/Vite; 35 тестов, включая авторегистрацию, изоляцию работ, права доступа, максимумы задач, сохранение оценок после перезагрузки и закрытие приёма при публикации итогов. В Chrome просмотрены список 12 участников, фильтр сданных работ и отдельные формы оценки хакатона и олимпиады.
