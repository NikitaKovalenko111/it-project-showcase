# Проверка текущей реализации и правок пользователя

Проверены код маршрутов и форм, переходы публикация → участие → выполнение → проверка → итоги → портфолио/отчёты, правила доступа и существующие автоматические проверки. Это аудит текущего фронтенда и mock-сервера, не заключение о готовности production-бэкенда.

## Исправлено в этом проходе

1. **Этапы выполнения.** Раньше результаты были разделены по командам, а материалы и статусы этапов оставались общими. Теперь у выполнения свой набор этапов, файлов и решений проверяющего. Шаблон задаётся в общем плане; новые этапы добавляются в выполнения, изменения неиспользованного этапа синхронизируются. Ранее принятые материалы сохраняются. Удаление последнего файла снимает статус сдачи. После итоговой оценки материалы фиксируются.
2. **Составы команд.** Состав выполнения обновляется из подтверждённого состава команды. Приглашение само по себе не даёт членства; права на материал определяются участием именно в этом выполнении.
3. **Аналитика.** Вместо одной старой оценки на кейс загружаются оценки всех выполнений и их этапы. Средние оценки нормализуются к шкале 100, поэтому 18/20 и 90/100 сопоставимы. По кейсу выводится среднее, а не первая найденная оценка.
4. **Портфолио.** Подтверждённый проект появляется у участника с оценённой работой после завершения проекта. Одна регистрация без сдачи не становится подтверждённым достижением. Фотографии собственных сертификатов остаются отдельным разделом.
5. **Завершение проекта.** После публикации итогов обновляются списки кейсов и открытая карточка в Redux; форма не продолжает показывать прежний статус.
6. **NDA.** Модалка ждёт успешного ответа API. Ошибка видна пользователю и не открывает ТЗ. При переходе на другой кейс локальный флаг согласия сбрасывается.
7. **Ошибки проектов.** Ошибки открытия, создания и лайка студенческого проекта теперь выходят из состояния загрузки и попадают в состояние ошибки. Ошибка доступа не превращается в бесконечный индикатор.
8. **Состояние форм.** Видимость синхронизируется с открытым проектом. После сохранения решения и оценки состояние формы обновляется. При выходе очищается refresh-токен. Демо-переключатель ролей скрыт в live-режиме.
9. **Граница mock/live.** Для шести ещё не подключённых операций (`getFavorites`, `toggleFavorite`, `isNDAAccepted`, `acceptNDA`, `toggleStudentProjectLike`, `verifyCompany`) запрещена тихая запись в mock при live-режиме. До согласования реального API выводится явная ошибка вместо фиктивного успеха.

## Сверка с последними правками

| Требование | Текущее поведение |
|---|---|
| Нет пагинации на главной студента и компании | Главная использует обычные сетки без контролов страниц |
| Пагинация слева в каталогах | Общее выравнивание влево |
| При прокрутке возвращается только поиск | Отдельная компактная строка, порог движения вверх 90 px и плавный переход |
| Логика команды и приглашений | Создание → карточка своей команды → приглашение → согласие адресата; поиск команды по проекту отдельно |
| Без дублированного заголовка поиска | Выбор проекта и результаты поиска объединены; настройки не повторяются на карточке |
| Компактные настройки проекта | Только внутри проекта, свёрнутый блок |
| Олимпиада без отбора организатором | Открытая регистрация сразу создаёт участие |
| Оценивание олимпиады | Баллы за задачи с отдельными максимумами; автоматический judge не реализован |
| Оценивание кейса/хакатона | Критерии, веса, независимые работы и оценки |
| Много команд у организатора | Общий список, поиск, фильтры, отдельные работы и этапы; три демо по 12 участий |
| Проектная команда | Участники со ссылками на профили вместо неработающего перехода |
| Заявки на отбор отдельно от регистраций | Отдельный раздел заявок и контекстная ссылка из кейса; события имеют список участников |
| Итоги | Публикуются после проверки сданных работ, закрывают приём, фиксируют оценки |

## Проверка

- Production-сборка TypeScript/Vite.
- 37 тестов: права ролей, приватность, авторегистрация, сохранение после перезагрузки, изоляция работ и материалов этапов, ограничения оценки, завершение мероприятия и подтверждённое портфолио.
- Chrome: открытие рабочего пространства обычного кейса, выбор команды, просмотр её состава, этапов, материалов и оценки.
- Полная ручная проверка каждой страницы на всех мобильных размерах, Firefox/WebKit и реального сервера не выполнена.

## Оставшиеся границы

Серверные контракты по-прежнему требуют согласования: execution, материалы, NDA, избранное, модерация ревизий и consent участников. Новые методы `updateExecutionStage` и `getStudentAchievements` используют текущий временный `/community/<method>` контракт. Маппинг всех моделей на канонический API, UUID-справочники и серверная пагинация не считаются завершёнными.

Автоматическая проверка программ олимпиады, отдельные чаты каждого выполнения и полный процесс модерации версий не добавлены. Общий чат остаётся обсуждением проекта; файлы команды сдаёт и проверяет в своём выполнении.
