# Кабинет компании: проекты и мероприятия

## Путь организатора

1. **Активные проекты → Проекты и мероприятия компании.** Фильтры «Кейсы», «Хакатоны», «Олимпиады», «Стажировки», поиск и статус. Компания видит только свои публикации, включая ожидающие модерации. На карточке указан тип.
2. **Команды и решения / Участники и работы.** Общий список с прогрессом этапов, количеством этапов на проверке, статусом финального решения и баллами. Поиск по составу и названию; отдельные фильтры сданных работ и этапов на проверке.
3. **Работа конкретной команды.** Состав, отдельные контрольные точки, файлы, рецензии, итоговое решение и оценка. Принятие этапа одной команды не принимает его у остальных. Для хакатона используется оценка по критериям; для олимпиады — баллы за задачи.
4. **Общий план реализации / Расписание туров.** Редактор структуры мероприятия, описанный ниже.
5. **Итоги и рейтинг.** Общая таблица и публикация итогов после проверки сданных работ. Публикация закрывает приём и фиксирует оценки.

Общее обсуждение и условия доступны отдельными кнопками. Ссылка на заявки отбора показывается для кейсов и стажировок; открытые регистрации на хакатон/олимпиаду рассматриваются как участия.

## Общие контрольные точки

Организатор добавляет этапы, меняет название, описание, срок и порядок. Сроки можно сдвинуть сразу у всех этапов на положительное или отрицательное число дней. До сохранения изменения можно отменить.

Сохранение обновляет метаданные этапов во всех выполнениях, включая новые команды. Прогресс, загруженные файлы, рецензии и принятые этапы сохраняются отдельно по командам. Нельзя удалить использованный этап: при наличии материалов или начала работы сохранение отклоняется. Неиспользованный этап удаляется у всех. Порядок этапов синхронизируется во всех выполнениях.

Срок этапа не может быть позже срока проекта. Чтобы продлить мероприятие, сначала меняют срок публикации. После публикации итогов общий план доступен только для чтения.

## Демо и проверка

В mock-хранилище есть обычный кейс, хакатон и олимпиада по 12 участий. Для них однократно добавляются общие планы из трёх этапов. Пользовательские записи не удаляются; намеренно удалённые демо-этапы не восстанавливаются при каждом запуске.

TypeScript/Vite build и 39 тестов проходят. Новые тесты проверяют синхронизацию плана на 12 командах, сохранение материалов и рецензии принятого этапа, смену порядка, запрет удаления использованного этапа, удаление неиспользованного этапа, права организатора и запрет изменения после завершения.

В Chrome просмотрены обзор хакатона и форма общего плана. Полный мобильный и межбраузерный прогон не выполнялся.

## Серверная интеграция

Новые операции `getSharedPlan` и `updateSharedPlan` используют временный фронтендовый контракт `POST /community/<method>`. Проверена mock-реализация; наличие этих операций на настоящем бэкенде не подтверждено.
