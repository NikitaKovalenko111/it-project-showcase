# Фронтенд для повторного тестирования — 01.11.2026

## Объем изменений

- Витрина: удалены строка учебного года/даты публикации и все технологические чипы со скриншотов. Поиск и направление сохранены; селект уровня расширен до 210 px. ID пользователя под именем скрыт для всех ролей.
- Публикации компании: выбор «Кейс / Олимпиада / Стажировка», обязательный регламент олимпиады или условия стажировки для соответствующего типа, длительность, размер команды, максимум команд либо отсутствие ограничения. Компания редактирует собственную опубликованную карточку через «Редактировать кейс». Редактирование не добавляет дубликат в список. Первичная публикация проходит модерацию.
- Команды: создание в собственном профиле, поиск участников по имени/почте, приглашения с подтверждением, входящие/исходящие заявки. В отклике доступны реальные команды капитана и переход к созданию команды/приглашениям. Фиктивная команда из формы удалена.
- В кейсе есть поиск команды: мини-анкета со стеком, список набирающих команд, заявки на вступление, просмотр профилей и приглашение кандидатов капитаном. Объявление набора отдельно от участия: оно не дает прав сдавать материалы до принятия заявки компанией.
- Во вкладке команд компании видны принятые команды и ссылки на участников. В рабочей станции сохранены этапы, оценка и обсуждение, добавлен список заявок с решениями и интервью. Лимит блокирует прием сверх установленного числа; уменьшение ниже уже принятого числа запрещено.
- Компания заполняет собственную программу стажировок, описание сохраняется. Во вкладке кейсов компании появились поиск, направление, статус и сортировки по дате, дедлайну, заявкам.
- Аналитика компании: «Аналитика кейсов», широкая первая колонка, таблица «Компании» убрана из экрана и экспорта; направления, технологии и этапы сохранены. У администратора добавлены роли пользователей, блокировки, студенты без куратора, жалобы и последние события аудита.
- Студенческие проекты: приватное создание, выбор видимости в «Моих публикациях», отправка на общее обозрение через модерацию. Приватные проекты доступны только автору, включая прямые ссылки; повторное открытие после приватного состояния требует проверки.
- Комментарии кейса: ответы, лайки с переключением, сортировки по времени, лайкам и популярности (лайки + ответы).
- Жалобы: кейс, студенческий проект, комментарий, профиль; причина и пояснение. Администратор рассматривает жалобы; повторная открытая жалоба на тот же объект от одного пользователя блокируется.
- Приглашения: отдельная страница с кейсом/компанией, отправителем, причиной и сообщением, перепиской, принятием/отклонением. Решение окончательное. Компания получает ответное уведомление. Согласие на приглашение компании отдельно от заявки на выполнение кейса; после согласия доступен переход к подаче заявки.
- Каталог студентов: уровни обучения, курсы 1–6, рейтинг по убыванию; куратор назначает студентов себе, сотрудник/администратор выбирает куратора. Отдельный поиск по группе, фильтр «Мои студенты». Уровень обучения заполняется в профиле, для старых записей без этого поля он не выдумывается.

## Запуск

Из корня репозитория: `npm --prefix frontend ci`, затем `npm --prefix frontend run dev`. Режим тестирования — `VITE_API_MODE=mock`. Для чистого прогона используйте новый профиль браузера или отдельный origin, не удаляя нужные данные основного стенда. Демо-роли переключаются через меню справа сверху. Второго студента можно открыть через демо-вход по его username из `src/api/mockData.ts`.

Архив `frontend-testing-2026-11-01.zip` содержит production-сборку `dist` и этот документ. Для раздачи нужен статический сервер с fallback на `index.html` для маршрутов SPA. Открытие `index.html` через `file://` не поддерживается.

## Регрессия для Радмира

1. Студент: проверить отсутствие двух удаленных строк, отображение «Уровень: любой» целиком на desktop и mobile.
2. Компания: создать по публикации каждого типа, проверить обязательные поля, лимит и модерацию; отредактировать опубликованную карточку, обновить страницу, убедиться, что дубликата нет.
3. Два студента: создать команду, найти второго по почте, пригласить; до согласия состава не менять. Принять со второго аккаунта, обновить страницу; повторное решение не должно работать.
4. В кейсе: опубликовать анкету без команды, пригласить по анкете либо отправить заявку в набирающую команду; проверить входящие/исходящие у капитана. Набирающая команда не может сдавать материалы до одобрения компанией.
5. Компания: принять несколько разных заявок до лимита, следующую отклонить валидацией. Проверить команды, профили, интервью и оценку в рабочей станции.
6. Проект студента: создать приватным, проверить отсутствие у другого студента и куратора; отправить на общее обозрение, одобрить куратором, проверить каталог; снова скрыть.
7. Комментарии: написать вопрос и ответ, поставить/снять лайк, проверить три вида сортировок и сохранение после обновления.
8. Жалобы: отправить с причиной и пояснением, проверить дубликат, рассмотреть администратором.
9. Компания → студент: приглашение → уведомление → отдельная страница → ответ → принятие/отклонение. Проверить данные отправителя и компании, отсутствие повторных кнопок решения.
10. Стажировка компании: заполнить программу, перезагрузить, проверить доступность чтения студенту и отсутствие права редактировать.
11. Куратор: найти группу, закрепить студента, включить «Мои студенты»; проверить рейтинг по убыванию и уровни обучения.
12. Аналитика: у компании нет таблицы «Компании» на экране и в экспортах, название кейса читается; у администратора доступны дополнительные сведения и жалобы.

## Проверено в этом проходе

Сборка TypeScript/Vite и автоматические тесты. В Chrome вручную проверены удаление строк, смена полей стажировки, создание команды, поиск по почте и исходящее приглашение, комментарий и лайк, форма жалобы, назначение куратора и поиск группы, сохранение программы стажировки, приглашение компании → уведомление → страница → ответ → принятие. Витрина на 390 px и поиск команды на 320 px без горизонтального переполнения. Полного WebKit/Firefox e2e-прогона нет.

## Контракт для бэкенда

Новые действия вызывают `POST /api/v1/community/<method>` с JSON `{ "args": [...] }`. Имена методов, порядок параметров и возвращаемые модели определены в `src/api/community.ts`, `src/types/models.ts` и одноименных методах mock-сервера. Это предложенный фронтендовый контракт, пока не подтвержденный серверной реализацией.

Методы: `reportContent`, `getReports`, `resolveReport`, `setStudentProjectVisibility`, `updateCompanyContent`, `assignStudentCurator`, `likeComment`, `getTeamRequests`, `requestTeam`, `decideTeamRequest`, `getSeekers`, `saveSeeker`, `linkTeamToCase`, `getInvitation`, `respondInvitation`.

Остальные затронутые live-запросы: `GET /students`, `GET/POST /teams`, `GET/POST /cases/:id/comments`, `POST /invitations`, `GET /notifications`, `PATCH /notifications/:id/read`, `POST /notifications/read-all`, `GET /audit-logs`; создание/редактирование кейса использует прежний API. Сервер должен повторять проверки ролей, приватности, лимитов и атомарности решений. В live-режиме ошибки новых запросов выводятся пользователю, запись в mock не подставляется.

В модели по-прежнему один итоговый результат и оценка на кейс: отдельная приемка результата каждой из нескольких команд требует расширения серверного контракта. Расширенные административные сведения показаны отдельным блоком; существующие выгрузки остаются отчетами проектной деятельности. Расшифровка созвона Радмира не предоставлена.
