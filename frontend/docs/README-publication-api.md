# API формы «Разместить публикацию»

Форма доступна представителю компании. В режиме работы с сервером фронтенд подставляет `company_id` из привязанной компании и показывает её название в поле только для чтения. Если доступной компании нет, форма сообщает об этом.

Пути в примерах указаны относительно базового URL API. По умолчанию это `/api/v1`.

| Формат публикации | Запрос создания | Поле, определяющее формат |
| --- | --- | --- |
| Кейс | `POST /cases` | `event_format: "case"` |
| Хакатон | `POST /cases` | `event_format: "hackathon"` |
| Олимпиада | `POST /cases` | `event_format: "olympiad"` |
| Стажировка | `POST /internships` | `kind: "internship"` |
| Практика | `POST /internships` | `kind: "practice"` |

## Кейс, хакатон и олимпиада

### Поля `POST /cases`

| Поле | Значение при создании |
| --- | --- |
| `company_id` | ID привязанной компании. |
| `title` | Название публикации. |
| `summary` | Краткое описание. |
| `full_brief` | Полное ТЗ, задачи или описание заданий и туров. |
| `type` | `contest`. |
| `event_format` | `case`, `hackathon` или `olympiad`. |
| `difficulty` | `beginner` — начальный, `intermediate` — средний, `advanced` — высокий. |
| `work_format` | `remote` — дистанционный, `onsite` — очный, `hybrid` — смешанный. |
| `participation_mode` | `individual` — только индивидуально, `team` — только командами, `both` — оба варианта. |
| `admission_mode` | `selection` для кейса, `open` для хакатона и олимпиады. |
| `capacity` | Лимит от 1 до 10 000. При `individual` считается число участников, при `team` — число команд. При `both` один индивидуальный участник и одна команда занимают по одной единице лимита. |
| `team_size_min`, `team_size_max` | Границы размера команды от 1 до 100, минимум не выше максимума. Пара `1, 1` используется только для `individual`. Для `team` и `both` максимум начинается с 2. |
| `application_deadline` | Срок подачи заявок или регистрации. Фронтенд преобразует `23:59:59` выбранного дня по местному времени браузера в ISO-строку UTC. Для хакатона и олимпиады срок обязателен, для кейса — по желанию. |
| `due_at` | Дедлайн защиты или окончания мероприятия. Фронтенд преобразует конец выбранного местного дня в ISO-строку UTC. |
| `direction_ids` | Массив с ID выбранного направления из справочника или `[]`, если направление не выбрано. |
| `required_competencies` | Массив объектов `{ id, required_level }`. При создании `required_level` — пустая строка. |
| `technology_ids` | `[]`. |
| `evaluation_criteria` | Для кейса и хакатона — массив объектов `{ name, max_score, ordinal }`. `ordinal` начинается с `1`. Для новой олимпиады отправляется `[]`. |
| `evaluation_rules` | Для олимпиады — текст из поля «Регламент и правила оценивания». Для кейса и хакатона — текст «Оценка по N критериям». |
| `rewards` | Массив с одной записью о призовом фонде. В запись входят `kind: "prize"`, `description`, `amount: null`, `prize_fund`, `currency: "RUB"` и `prize_places: []`. |
| `result_requirements` | Для кейса и хакатона — «Прототип, презентация и демонстрация решения». Для олимпиады — «Решения заданий по турам и пояснения». |
| `ip_terms` | `author`. |
| `nda_required` | `true` при включённом NDA для кейса или хакатона с командным или смешанным участием. В остальных случаях — `false`. |
| `visibility` | `public`. |
| `duration` | Пустая строка. |
| `files` | Массив `[{ "file_id": "…", "visibility": "public" }]` с загруженным файлом ТЗ или `[]`. |

Поля `course_min` и `course_max` при создании новой публикации отсутствуют в JSON. Для направления и компетенций фронтенд получает ID через `GET /catalogs/directions` и `GET /catalogs/competencies`.

### Файлы, NDA и модерация

1. Если выбран файл ТЗ или обложки, фронтенд загружает каждый файл через `POST /files` с полем `file` в `multipart/form-data`.
2. Фронтенд создаёт черновик через `POST /cases`. ID файла ТЗ передаётся в массиве `files`.
3. Для загруженной обложки фронтенд вызывает `PUT /cases/{case_id}/cover` с телом `{ "file_id": "…" }`.
4. Если включён NDA и введён текст, фронтенд сохраняет версию через `POST /cases/{case_id}/nda-versions` с телом `{ "text": "…" }`. При `nda_required: true` сервер требует действующую версию перед отправкой на модерацию. При её отсутствии API отвечает `409 nda_version_required`, а фронтенд предлагает открыть редактирование и сохранить NDA.
5. Для кейса кнопка «Отправить на модерацию» вызывает `POST /cases/{case_id}/submit-moderation`. Для хакатона и олимпиады кнопка «Создать черновик и настроить план» открывает настройку мероприятия после сохранения черновика.

## Стажировка и практика

### Поля `POST /internships`

| Поле | Значение при создании |
| --- | --- |
| `kind` | `internship` для стажировки или `practice` для практики. |
| `company_id` | ID привязанной компании. |
| `title` | Название программы. |
| `summary` | Краткое описание. |
| `content_markdown` | Программа и условия участия в Markdown. |
| `capacity` | Количество мест от 1 до 10 000. |
| `application_deadline` | Дата окончания приёма заявок. Фронтенд берёт `23:59:59` по местному времени браузера и преобразует в ISO-формат. При пустом поле отправляет `null`. |
| `file_ids` | Массив UUID вложений. При сохранении фронтенд передаёт полный список, включая уже прикреплённые файлы. |

### Пример тела запроса для практики

```json
{
  "kind": "practice",
  "company_id": "11111111-1111-4111-8111-111111111111",
  "title": "Практика по тестированию веб-приложений",
  "summary": "Практика в команде контроля качества.",
  "content_markdown": "## Программа\nПодготовка тест-кейсов и проверка интерфейса.",
  "capacity": 5,
  "application_deadline": null,
  "file_ids": []
}
```

### Фото в Markdown

1. При первой загрузке фото фронтенд сохраняет черновик через `POST /internships` и получает `program_id`. Для существующей программы используется её ID.
2. Фото загружается через `POST /files` с Bearer-токеном и полем `file` в `multipart/form-data`. Сервер возвращает `file_id`.
3. В `content_markdown` добавляется постоянная ссылка вида `![Фото офиса](/api/v1/internships/PROGRAM_ID/files/FILE_ID/content)`. Если API настроен на другом домене, фронтенд использует полный URL этого API.
4. Фронтенд отправляет через `PUT /internships/{program_id}` всю форму, включая обновлённый Markdown и весь массив `file_ids`. Сервер связывает фото с программой.

В опубликованной программе браузер загружает фото через маршрут программы без Bearer-токена. Для предпросмотра черновика фронтенд получает изображение тем же маршрутом через авторизованный API-клиент и показывает его через временный object URL. В Markdown хранится только постоянная ссылка API.

Старые ссылки на `/files/{file_id}` можно просмотреть в редакторе с правами на исходный файл. Чтобы сделать такие фото доступными читателям, добавьте их через «Добавить фото в текст» и удалите старые ссылки из Markdown.

Кнопка «Сохранить черновик» создаёт новую программу или обновляет существующую. Кнопка «Отправить на модерацию» после сохранения вызывает `PATCH /internships/{program_id}/status` с телом `{ "status": "moderation", "comment": "" }`.
