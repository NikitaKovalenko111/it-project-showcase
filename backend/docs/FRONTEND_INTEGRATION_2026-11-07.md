# Сверка интеграции от 7 ноября 2026

В отчёте фронтенда раздел повторной интеграции заменяет результаты от 5 ноября по форматам событий, контрольным точкам и куратору. Ниже маршруты указаны относительно `/api/v1`. Полный контракт описан в [API.md](API.md) и [Swagger](openapi.yaml).

## Что подключить на фронтенде

| Экран | Изменение |
| --- | --- |
| Мониторинг куратора | Загружать `GET /executions?limit=20&cursor=…` с Bearer. Ответ содержит `items` и `next_cursor` верхнего уровня. Открывать этапы и комментарии по `execution_id`. Сдачи, защищённые файлы и оценки требуют отдельного решения по правам куратора. |
| Редактор этапов | На странице управления кейсом отправлять Bearer в `GET /cases/{case_id}/stages`. Для перестановки передавать полный массив `stage_ids` в `PUT /cases/{case_id}/stages/order` и использовать возвращённый порядок. При `409 case_stages_locked` перечитать этапы и переключить интерфейс в режим просмотра. Для серии отдельных запросов сохранить перечитывание при частичной ошибке. |

| Персональные приглашения компании | Подключить существующие `GET /company-invitations` и `PATCH /company-invitations/{invitation_id}`. В интерфейсе доступны принятие и отклонение. Текстовая переписка и обратное уведомление о решении исключены предыдущим согласованием. |
| Формы заявок | Сохранять автоподстановку из `GET /application-defaults`. В отправляемую заявку передавать только выбранные пользователем значения и идентификаторы. |

В отчёте фронтенда также указаны собственные добавления `GET /users`, `GET /companies/mine`, `GET /cases/mine` и `GET /teams/mine`. В локальном backend этой работы они отсутствуют. Перед объединением веток нужно перенести проверенные реализации с интеграционного стенда.

## Что исправлено в backend

- Добавлен `GET /executions`. Проверка доступа использует те же условия, что и карточка выполнения. Для куратора требуется активное назначение на студента, который остаётся участником этого выполнения.
- Чтение этапов учитывает необязательный Bearer и безопасно обрабатывает гостевой запрос. Перестановка выполняется одной транзакцией с сохранением положительных порядковых номеров. После первого выполнения любые изменения плана возвращают `409 case_stages_locked`.
- `POST /reports` принимает жалобу на одобренную компанию. База проверяет цель, а API возвращает `404` для отсутствующей или недоступной компании.
- Добавлены идемпотентные лайки активных публичных комментариев и ответов. База допускает одну отметку от пользователя на комментарий, сервер вычисляет итоговый счётчик.
- Добавлен список всех проектов текущего владельца, включая черновики, приватные проекты и проекты на модерации.
- Добавлены редактирование стажировки управляющим представителем и очередь стажировок для администратора. Изменение опубликованного объявления переводит его в `revision`.
- Добавлен список исходящих кандидатур студента. Выборка ограничена текущим пользователем.
- Миграция `000013` добавляет поддержку атомарного изменения порядка, проверку целей жалоб, таблицу лайков комментариев и индекс списка исходящих кандидатур.
