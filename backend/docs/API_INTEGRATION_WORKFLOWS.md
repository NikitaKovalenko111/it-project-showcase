# Дополнение к контракту интеграции

Пути ниже указаны относительно `/api/v1`. Подробные схемы запросов есть в [Swagger](openapi.yaml).

## Профиль и доступ

- `POST /auth/register` принимает необязательное поле `role`. Студент по-прежнему регистрируется сразу. Представитель компании и куратор ждут решения модератора. `POST /auth/login` возвращает `403 role_approval_pending` или `403 role_request_rejected` после проверки пароля. Токены выдаются после одобрения.
- `GET /users?page=1&page_size=20` доступен модератору и возвращает `requested_role`, `role_request_status` и назначенные `roles`. Решение отправляется в `PATCH /users/{user_id}/role-request` с `status: approved|rejected`.
- `PUT /students/me/profile` заменяет личные, учебные и портфолио-поля профиля. Обязательны `email`, `first_name`, `last_name`, `institute`, `direction`, `course`, `group_name`. `education_level` необязателен. Фото и приватное резюме управляются существующими маршрутами загрузки. После `204` клиент может перечитать `GET /auth/me`.
- `GET /companies/mine` и `GET /cases/mine` используют `limit`, `cursor` и возвращают `{items, next_cursor}`. Компании фильтруются по активным членствам, кейсы — по разрешению `manage_company`. `GET /teams/mine` и `GET /users` используют `page`, `page_size` и возвращают `{items, page, page_size, total}`.

## Регистрация и заявки

| Вид | Действие | Лимит |
| --- | --- | --- |
| Кейс | `POST /applications` и решение компании | Команды |
| Хакатон, олимпиада | `POST /event-registrations` | Команды |
| Стажировка | `POST /internships/{program_id}/applications` и решение компании | Люди |

При создании кейса, хакатона и олимпиады обязательны `capacity`, `team_size_min`, `team_size_max`. Индивидуальное участие задаётся размером `1–1` и `participation_mode=individual`. В смешанном формате диапазон размера применяется только к командам. Стажировка при создании требует `capacity`. В старых записях лимиты могут отсутствовать.

Для регистрации передайте `case_id`, `applicant_type: individual|team` и `team_id` для команды. Индивидуальная запись подтверждается сразу и возвращает `execution_id`. Команда сначала получает `consent_pending`; каждый участник подтверждает ту же версию условий через `POST /applications/{application_id}/consents`. Сервер учитывает согласие капитана при подаче. Поле `can_consent` показывает, может ли текущий участник подтвердить условия. Место занимает подтверждённая команда. При заполненном мероприятии сервер возвращает `409 event_capacity_reached`. Старые записи заявок сохраняют свой тип.

Для закрытого мероприятия регистрирующийся участник или капитан должен предварительно принять персональное приглашение компании.

Для стажировки студент может передать `cover_letter` и выбранный `resume_file_id`. Компания читает заявки в `GET /internships/{program_id}/applications`; студент — в `GET /internships/applications/mine`. В `PATCH /internships/applications/{application_id}/status` компания передаёт `accepted` или `rejected`, студент может передать `withdrawn` для своей заявки. При заполненном лимите принятие возвращает `409 internship_capacity_reached`. Резюме скачивается защищённым `GET /internships/applications/{application_id}/resume`.

## Мероприятия и туры

Компания сохраняет план черновика через `PUT /cases/{case_id}/event-plan`. `work_format` хранится у кейса. Для очного формата план содержит `venue_name` и `address`, для онлайн — `platform_name` и `platform_url`, для смешанного — оба набора. `building` и `room` необязательны. `time_zone` — имя часового пояса IANA. Срок регистрации берётся из `application_deadline` кейса, общий срок сдачи — из `due_at`. У хакатона также есть `agenda` и необязательный `defense_at`.

Для отправки на модерацию нужен сохранённый план и срок регистрации. Для хакатона также обязателен общий срок сдачи, для олимпиады — хотя бы один тур. При недостающих данных сервер возвращает `422 event_plan_required`.

Туры расположены в порядке массива `rounds`. У каждого есть `title`, `opens_at`, `due_at`, `rules` и `tasks`. У задания есть `title`, `statement`, `file_ids` и `max_score`. Сервер выдаёт идентификаторы туров и задач. Полная замена плана в черновике создаёт их заново, после первого выполнения план блокируется. Если олимпиада однотуровая, фронтенд формирует один тур автоматически.

`GET /cases/{case_id}/event-plan` отдаёт публичный регламент и расписание опубликованного мероприятия. Условия, файлы и ссылка на онлайн-площадку доступны в пределах прав участника. Задания и прямое скачивание по `GET /cases/{case_id}/rounds/{round_id}/tasks/{task_id}/files/{file_id}` открываются не раньше `opens_at`. Для просмотра до открытия доступ есть у управляющей компании и модератора.

- `POST /executions/{execution_id}/rounds/{round_id}/submission` принимает `solutions`. Для каждого решённого задания передайте `task_id` и текст, файл или ссылку. Один участник команды сдаёт общую работу за всё выполнение. Повторная сдача возвращает `409 event_round_already_submitted`, сдача вне окна — `409 event_round_closed`.
- `PUT /executions/{execution_id}/rounds/{round_id}/evaluation` принимает `scores` с баллом за каждое задание. Оценивать может управляющий представитель или модератор. Сервер проверяет `max_score` и суммирует баллы.
- `GET /executions/{execution_id}/round-submissions` возвращает работы, баллы по заданиям и сумму по оценённым турам. Имя оценившего и метаданные файлов возвращаются компании и модератору. Файлы решений доступны по `GET /executions/{execution_id}/rounds/{round_id}/files/{file_id}` участникам этого выполнения, управляющей компании и модератору.

## Перенос сроков и счётчики

Управляющая компания меняет срок через `PATCH /cases/{case_id}/deadline`, `PATCH /cases/{case_id}/stages/{stage_id}/deadline` или `PATCH /cases/{case_id}/rounds/{round_id}/deadline`. Тело содержит новый `due_at` и `reason`. Срок применяется ко всем активным выполнениям, предыдущая дата сохраняется в истории. На сайте приходит уведомление `case_deadline_changed`. Для тура дедлайн должен быть позже открытия.

Компания и модератор читают историю через `GET /cases/{case_id}/deadline-history` с параметрами `page` и `page_size`.

Публичная карточка кейса содержит `registrations_count`, `applications_count` и `views_count`. Для хакатона и олимпиады фронтенд показывает число подтверждённых регистраций. Для кейсов счётчик заявок исключает отозванные и отклонённые. `PUT /cases/{case_id}/view` отправляется при открытии карточки авторизованным пользователем. Повторное открытие тем же аккаунтом не увеличивает число просмотров.

`GET /submissions/{submission_id}/review-details` возвращает имена оценивших и метаданные файлов обычного результата управляющему представителю компании или модератору.

## Обратная связь

Автор сначала загружает файлы через `POST /files`, затем передаёт `body` и `file_ids` в `POST /feedback`. Допускается до пяти своих файлов не больше 2 МиБ каждый. Начальное состояние `reviewing` («На рассмотрении»). Модератор читает очередь через `GET /feedback` и отправляет решение `accepted` или `rejected` в `PATCH /feedback/{feedback_id}/status`. Автор отслеживает состояние через `GET /feedback/mine`. Вложения скачивают только автор и модератор через `GET /feedback/{feedback_id}/files/{file_id}`.

## Вопросы для созвона

- **Практики.** Это отдельный сценарий. Нужны обязательные поля, участники процесса, правила публикации и шаги после подачи заявки.
- **Назначение куратора.** Сейчас доступны самоназначение и назначение модератором. Нужно подтвердить, требуется ли согласие студента и кто может отзывать связь.
