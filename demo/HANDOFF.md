# Передача разработчику — версия 0.2

Работа ограничена demo. Frontend, backend, конфигурация и миграции для подключения материалов не менялись.

## Источники и типы материалов

sources/content-provenance.json связывает ID с происхождением записи:
- official_profile — профиль реальной компании/организации;
- historical_event — прошедшее мероприятие с датами из источников;
- published_case_summary — краткая передача опубликованного задания;
- original_concept — новая концепция;
- prototype_content — контент первой партии.

Названия компаний у новых концепций — отраслевой ориентир, а не подтверждённый заказ. Не показывать их как опубликованные компаниями вакансии или действующий приём: новые концепции имеют status=draft. Финансовые условия и участие в мероприятиях не распространяются на другие материалы автоматически.

Для интерфейса использовать содержательные поля карточек; источники и технические примечания не добавлять в каждый абзац описания.

## Архив

7 событий и 4 опубликованных кейса имеют status=archived и фактические даты завершения. В data/historical-events.json отдельно записаны начало, конец, место и источники дат. Для GameJam даты относятся ко всей программе 13–21 сентября, а не девятидневному хакатону. Для фестиваля ТОП-ИТ указан проектный трек 25 сентября — 1 октября; открытие всего фестиваля — 24 сентября.

Дата новости не подставляется вместо даты события. Два мероприятия с неподтверждённым точным днём вынесены в sources/research-queue.json; их не следует добавлять в календарь с датой публикации новости.

Неизвестные поля архива (teamSize, complexity, duration, ipRights, publishedAt) могут быть null. Это осознанное расширение формата пакета относительно интерфейсов TypeScript: перед импортом нужен адаптер и отображение «Не указано», а не догадка. Призовой фонд заполнен только там, где подтверждён; исторические тарифы и условия не переносятся на будущие мероприятия.

## Форматы и связи

JSON — машинное представление, Markdown — для редакторской проверки. При правках синхронизировать обе версии. Префикс syn_ сохранён для устойчивых связей; это технический ID. Programs используют snake_case из Opportunity. При backend-импорте нужна проверка DTO, enum и отображение ID.

companyId → companies.id; authorId/studentId → students.id; caseId → cases.id; teamId → teams.id. Скрипты импорта описаны ниже.

## Медиа и вложения

Пути указаны относительно `demo/`. Импортёр загружает портреты, логотипы, обложки кейсов и проектов через API и сохраняет привязки в базе. Связи исходных материалов описаны в `data/asset-links.json`. Фотографии обложек служат тематическими иллюстрациями.

## Импорт в Docker

Нужны Node.js 22 или новее и запущенное окружение `compose.demo.yaml`.
Из корня репозитория:

```powershell
.\demo\import.ps1
```

```bash
bash demo/import.sh
```

Оба скрипта запускают общий `import.mjs`. Он работает только с изолированной базой `showcase_demo`, сохраняет существующие записи и повторно исправляет связи ответов. Проверка SHA-256 позволяет пропускать уже загруженные фотографии и логотипы. Интерфейс показывает имена из ответов API.

Импорт также подключает обложки и скриншоты проектов, заполняет реакции, обсуждения, обратную связь и уведомления. Конкурсные карточки в портфолио помечены как демонстрационные. «Мониторинг перегрева насосов» — образовательный кейс без денежного вознаграждения. Публичные комментарии к студенческим проектам доступны через существующий API.

Статус индустриальных партнёров сверялся по [реестру ТОП-ИТ УУНиТ](https://uust.ru/it-training-center/rabotadateli/). Логотип «Газпром нефти» взят из [копии фирменного знака на Wikimedia Commons](https://commons.wikimedia.org/wiki/File:Gazprom_Neft_-_logo.png). Исходник логотипа IBS — [Эраст Зильбердович, Wikimedia Commons, CC BY-SA 4.0](https://commons.wikimedia.org/wiki/File:IBS_logo_new.png). Для аватарки IBS изменён размер, применяется [та же лицензия](https://creativecommons.org/licenses/by-sa/4.0/). Исходник Инносетей указан в реестре УУНиТ и в `data/partners.json`.

Дополнительные хакатоны и завершённые работы описаны в `company-cases.mjs`. Это учебные сценарии. Для студентов импорт создаёт завершённые работы с оценками и конкурсными наградами, прикрепляет резюме и демонстрационные сертификаты и добавляет уведомления. Рейтинг считается штатным представлением базы из работ, оценок, проектов и достижений. Все данные загружаются обоими скриптами импорта без пересборки фронтенда и бэкенда.

Для каждого студента импорт добавляет активную работу с двумя этапами. Промежуточный этап принят и оценён, итоговая защита остаётся в работе. `company-engagement.mjs` содержит учебные стажировки, практики и обсуждения. В кабинетах организаций также появляются отклики с резюме, приглашения и уведомления.

`company-demo-coverage.mjs` заполняет пробелы в кабинетах представителей. Для каждой организации с учебным аккаунтом есть открытый набор, проект в работе с наставником и оценённым этапом, завершённый кейс и обе категории программ. Для показа очереди добавлены заявки на рассмотрении, интервью, запрос уточнений, принятые и отклонённые заявки. В кабинетах IBS, Инносетей, Уфанета, Актиона и «Газпромнефть — Цифровых решений» доступны также учебные хакатоны и олимпиады.

Квадратные монограммы для вымышленных компаний, обложки, схемы прототипов и демонстрационные сертификаты подготовлены заранее. Для редактирования и повторного рендера используйте `render-pet-media.py` (Python, Pillow, Arial). При импорте галерей одинаковые файлы отсеиваются по SHA-256.

Эти же команды заполняют личные кабинеты существующих учебных аккаунтов. Для студентов берутся уровень образования, специализация и данные анкеты. Организации получают описания практики и стажировок из каталога. Для представителей, кураторов, проектного офиса и администратора подключаются имена и аватарки. Импорт дополняет пустые поля и заменяет исходный текст анкеты расширенной версией. Отредактированные анкеты и установленные пользователями аватарки сохраняются.

В этом наборе первые двадцать логинов имеют вид `demo.student1` — `demo.student20`, остальные студенческие логины — `syn_student_021` — `syn_student_060`. Представители используют логины своих организаций, например `demo.ibs`, `demo.inoseti`, `demo.gazprom`. Для куратора и администратора есть `demo.curator` и `demo.admin`.

`node demo/curate-media.mjs` повторно собирает уникальные обложки и проверяет локальные портреты, обложки и логотипы. Результат — `review/media-audit.json`. Отбор портретов основан на наличии одежды; национальность и этническая принадлежность не определяются.

Резюме и отчёты — Markdown; при необходимости преобразовать в PDF. Входные таблицы — небольшие собственные примеры; источники трёх новых JSON указаны в sources/input-provenance.json. Они не являются файлами прошедших хакатонов. Пустые контакты, репозитории и неподтверждённые сведения не заполнять случайными значениями.
