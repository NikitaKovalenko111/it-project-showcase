# Интеграция фронта с текущим бэком — 15.11.2026

Изменения ограничены фронтендом. Код, миграции, конфигурация и данные бэка не менялись.

## Подключено

- Live API по умолчанию при обычном запуске и Docker-сборке; отдельная команда `npm run dev:mock`.
- Чтение `next_cursor` верхнего уровня и `total` в постраничных ответах.
- Аватар любой роли через `PUT /users/me/avatar`, отображение `avatar_file_id`, fallback на студенческое фото.
- Атомарное сохранение общего плана через `PUT /cases/{id}/stages`: точные даты исходного снимка, новый порядок, причина переноса. Проверка устаревшего плана и ошибок блокировки сохраняется.
- Отзыв итогов через `DELETE /cases/{id}/leaderboard/placements`, публикация мест также для олимпиады.
- Отзыв кейса с модерации и возврат программы в draft через существующие серверные маршруты.
- Очередь стажировок/практик читает расширенную moderation-выдачу без подмешивания публичного каталога.
- Причина блокировки аккаунта передаётся серверу; жалобы на internship доступны.
- Новая версия итогового решения доступна в submitted без оценки; superseded-версии исключены из текущего результата. Файлы другого участника той же работы сохраняются при обновлении.
- Видео MP4/WebM до 20 МиБ, выбор файлов в основных формах согласован с поддерживаемыми форматами.
- Изменение оценки её автором до публикации мест; уровень образования из студенческого поиска.
- Сводка куратора получает доступные выполнения из `/executions`, не зависит только от публичного каталога кейсов. После обновления бэка куратор читает решения, вложения и опубликованные оценки закреплённых участников, включая туры олимпиады. В карточках и сводке отображаются реальные результаты.

## Обнаруженные ограничения и расхождения

1. **Сквозная проверка локально заблокирована.** На 15.11 Docker Engine недоступен (нет named pipe `dockerDesktopLinuxEngine`). Дополнительно по пути `backend/config/config.yaml` всё ещё находится каталог, а нужен файл. Предыдущий запуск API падал именно на чтении этого пути. Чтобы проверить сценарии в браузере, требуется запустить Docker и восстановить корректный локальный конфигурационный файл. Конфигурацию и сервисы бэка не меняли.
2. Бэк принимает JPG, PNG, WebP, PDF, TXT, ZIP, MP4 и WebM, но не DOC/DOCX/PPT/PPTX/GIF. Основные активные формы ограничены поддерживаемыми форматами. Старый ResultSubmissionModal работает только с mock-сценарием; live-сдача идёт из рабочего пространства по execution_id.
3. Расширенный `review-details` (имена оценивших и сведения для проверки) остаётся доступен компании и администратору. Куратор получает опубликованные оценки и файлы через обычные маршруты решений. Действия изменения и оценки куратору не предлагаются.

## Подключено после merge нового бэка 15.11

- Администратор меняет роль через `PATCH /users/{id}/role`; фронт переводит роли компании и куратора в `company_representative` и `university_staff`. После ответа 204 перечитывает серверный список. Своя роль и роль администратора не редактируются; ошибки сервера видны в интерфейсе. Пользователь предупреждён о необходимости повторного входа.
- Материал сданного этапа удаляется через `DELETE /submissions/{submission_id}/files/{file_id}`. Перед удалением фронт находит текущую, незаменённую сдачу этапа. Используется ID файла из карточки, а не потенциально устаревший индекс. При ошибке API файл остаётся в интерфейсе, ошибка показывается пользователю.
- Скачивание материала этапа отправляет Bearer через общий FileDownload вместо прямого перехода по защищённому URL.
- Куратор читает текущие сдачи и опубликованные оценки; доступна вкладка результата/оценки, файлы и решения туров. Сводка, статусы и баллы используют фактический ответ API.
