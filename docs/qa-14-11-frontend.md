Рабочая папка: `frontend`, ветка `feature-frontend`. Бэкенд, миграции и серверные модели не менялись. Коммиты и отправка в репозиторий не выполнялись.

## Изменения интерфейса

- Выровнены поля регистрации; логин изначально пустой.
- Убраны указанные поясняющие подписи, подъём кнопок при наведении и объёмные эффекты. У карточек обрезается декоративная полоса, вкладки остаются в одной строке, панели примыкают к вкладкам.
- Выпадающие списки получили общий вид меню, управление клавиатурой и перенос длинных пунктов. Нативные `select` продолжают хранить значения форм.
- Добавлена видимая пагинация в том числе для коротких списков; уменьшен размер страниц кейсов компании, активных проектов и команд.
- Сокращены отступы карточек, юридических сведений, модерации, форм и подтверждений. Фокус поиска охватывает всё поле. Длинные описания компаний сворачиваются; длинный текст команд переносится.
- В комментариях кнопка отправки находится рядом с полем. Сохранены аватарки/инициалы авторов.
- Пункт меню профиля называется «Мой профиль». Приглашение студента перенесено наверх рядом с действиями, добавлен переход назад. В просмотре достижения закрытие находится справа.
- Markdown студенческих проектов отображается как разметка. В описания программ можно загружать собственные изображения.
- В пространстве мероприятия восстановлен отдельный план мероприятия: площадка, программа, регламент и туры. Контрольные точки остаются отдельным планом выполнения. Компания редактирует доступный ей план, студенты и кураторы просматривают его.
- Обсуждение и материалы показываются для выбранного выполнения команды, без общей ленты всех решений. Переход из принятой заявки выбирает соответствующую работу.
- На главной куратора сохранены очереди модерации и переходы к рабочим разделам, добавлен компактный список ближайших сроков. Группы и карточки закреплённых проектов убраны.
- Модерация стажировок/практик: компактный список и переход к полной странице программы. Администратору доступны блокировка программ и студенческих проектов, действия блокировки оформлены одинаково.
- Убраны надписи о демообращении и сохранении в браузере. Вложения-изображения имеют миниатюры и просмотр. В моках администратору доступны «Рассмотрено», «Сделано», «Отклонено».

## Моки

Число исходных пользователей, проектов, команд и выполнений не увеличено. У команд 1–4 участника; есть оценённые, отправленные и незавершённые работы, разные объёмы материалов и длинные содержательные тексты. Программы компаний заполнены, ссылки на сайты используют зарезервированный адрес `example.org`: это вымышленные компании, реальные сайты им не приписываются.

Обновление сохранённых моков дополняет только пустые или узнаваемые исходные поля. Пользовательские описания, названия, загрузки и созданные записи сохраняются. Пространства обсуждения хранятся отдельно по `executionId`.

## Что требуется от бэкенда

### Отзыв с модерации

Существующий контракт не предоставляет компании отзыв кейса и не разрешает перевод стажировки/практики из `moderation` в `draft`. В моках отзыв реализован, в live показывается объяснение, запрос на несуществующий маршрут не отправляется.

Предлагаемый контракт для согласования:

- Кейс: отдельное действие владельца для отзыва `moderation → draft/revision`, без удаления задания, плана, файлов и истории. После правок нужна повторная отправка на модерацию.
- Программа: расширить существующий `PATCH /internships/{id}/status`, разрешив владельцу `moderation → draft`. Сохранить проверку принадлежности компании и запрет на произвольную публикацию без модератора.

После согласования маршрута кейса подключить его в `apiClient.withdrawCaseModeration`; для программы убрать временную проверку в `opportunityApi.setStatus`.

### Статусы обращений

Текущий live использует `reviewing`, `accepted`, `rejected`. Для промежуточного состояния «Рассмотрено» нужен `reviewed`; кнопка доступна пока только в моках. Фронтенд отображает `accepted` как «Сделано» по запросу пользователя. Нужно согласовать эту семантику либо добавить отдельный `done` и обновить отображение/переходы фронтенда. Желательно возвращать автора, время смены статуса и комментарий администратора.

### Проверить на интеграционном стенде

- `GET/POST /executions/{id}/comments`: проверка доступа компании, назначенного куратора и участников именно этого выполнения.
- `GET/PUT /cases/{id}/event-plan`: существующие серверные ограничения редактирования сохранены; изменение плана после начала работ требует отдельно согласованного правила.
- Файлы Markdown загружаются через существующий `POST /files`; просмотр должен разрешаться тем же пользователям, которым доступна публикация. Клиент запрашивает защищённые изображения с авторизацией.
- Модерация проектов студентов и программ использует существующие маршруты. Сервер остаётся источником прав доступа, фронтенд их не заменяет.

### Жалобы на стажировки и практики: требуется поддержка API

Во фронтендный `ContentReport.targetType` добавлено значение `internship` для обеих разновидностей программы. В моках жалоба сохраняется с `targetId = program_id`, отображается администратору и содержит ссылку на программу.

Для live требуется разрешить `resource_type: internship` в `POST /reports`, проверять существование и доступность программы, возвращать этот тип при чтении жалоб. Фронтенд пока показывает понятное сообщение вместо отправки заведомо неподдерживаемого запроса. Серверный код не менялся.
