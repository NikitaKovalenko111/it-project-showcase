# Размер загружаемых файлов: расхождение фронтенда и API

На фронтенде сняты искусственные ограничения размера у аватара, резюме, вложений, материалов решения, портфолио, обратной связи и изображений публикации. Сохраняется проверка формата файла и количества вложений.

В frontend/nginx.conf задано client_max_body_size 0: прокси фронтенда не ограничивает размер запроса.

Бэкенд не изменялся. По текущему коду backend/internal/services/files/service.go:
- UploadUserAvatar отклоняет исходящий аватар свыше 2 МБ.
- upload проверяет общий предел s.maxSize из object_storage.max_file_size / max_file_size.
- Видео MP4/WebM дополнительно ограничены 20 МБ.
- Обработчик /files в backend/internal/transport/http/handlers/file/handler.go использует MaxBytesReader с общим лимитом плюс 1 МБ на multipart.

Чтобы API также принимал большие файлы, нужно пересмотреть эти серверные проверки, параметры хранилища и ограничения внешнего ingress/proxy. Фронтенд не обещает успешную загрузку, если файл отклонён сервером: ошибка показывается пользователю.

Аватар перед сохранением обрезается на клиенте в 512×512, без ограничения размера исходного фото. Большие файлы в мок-режиме хранятся как Blob в IndexedDB, метаданные — в localStorage. После перезагрузки ссылки восстанавливаются. Доступное место определяется браузером; ошибка записи показывается пользователю.
