# Расхождения фронтенда с API

Ниже описано поведение при подключении к бэкенду версии `982d97a`. Локальный деморежим может поддерживать больше действий.

| Сценарий | Что поддерживает API | Как работает фронтенд |
| --- | --- | --- |
| Отзыв итогов | `PUT /cases/{id}/leaderboard/placements` публикует места после оценки всех выполнений, кроме отменённых. Маршрута отзыва нет. | Компания и администратор могут опубликовать итоги кейса или хакатона. После публикации отображается таблица мест. |
| Общий рейтинг олимпиады | Общий рейтинг строится по оценкам работ из `submissions`, а баллы за туры хранятся отдельно. | Для олимпиады отображаются баллы за туры. Публикация общего зачёта по этим баллам недоступна. |
| Контрольные точки | `POST /cases/{id}/stages`, `PATCH` и `DELETE /cases/{id}/stages/{stage_id}`, `PUT /cases/{id}/stages/order` доступны для черновика и публикации на доработке до появления выполнений. После публикации срок меняется отдельным запросом `PATCH /cases/{id}/stages/{stage_id}/deadline` с причиной. Единого запроса для сохранения плана нет. | В черновике можно добавлять, удалять, менять и переставлять точки. Из плана опубликованного проекта компания может перейти к переносу срока выбранной точки. Если один из запросов сохранения черновика завершится ошибкой, интерфейс перечитает сохранённый план. |
| Файлы результата | В списке решений есть ID, тип и порядковый номер вложения. `GET /submissions/{id}/review-details` возвращает имя, размер и MIME-тип компании и администратору. При скачивании сервер возвращает имя файла в `Content-Disposition`. | В карточке показан список файлов. В режиме проверки используются метаданные из API. Если метаданных нет, в списке показаны номера файлов, а скачанные файлы получают исходные имена. |
| Видео результата | `POST /files` принимает JPG, PNG, WebP, PDF, TXT и ZIP. В итоговом решении есть поле `demo_url`. | Фото, скриншоты и документы загружаются как файлы. Видео и демонстрации добавляются ссылкой. |
| Новая версия работы и оценки | При статусе выполнения `submitted` сервер ждёт проверки. Повторная отправка возможна при подходящем статусе выполнения. Файлы новой версии должны принадлежать отправителю. Опубликованную оценку нельзя перезаписать через маршрут создания оценки. | Форма сдачи учитывает статус выполнения. При смене отправителя нужные файлы загружаются заново. Компания может поставить первичную оценку. |
| Аватары | `PUT /users/me/photo` и `GET /students/{id}/photo` работают для студенческих фото. Общего API аватаров нет. | Без фотографии отображаются инициалы. Студенты могут загрузить фото в профиле. |
| Блокировка стажировок и практик | `GET /internships/moderation` выдаёт очередь, `GET /internships` выдаёт опубликованные программы. Администратор может перевести опубликованную программу в `hidden`. Закрытые программы заблокировать нельзя, общего списка скрытых программ нет. | Администратор видит очередь и опубликованные программы. После блокировки запись видна в текущем списке до его повторной загрузки. |
| Поиск студентов и сводка куратора | `GET /students/search` не возвращает группу, уровень обучения и ID куратора. `GET /students/{id}/curator` проверяет назначение для одного студента. `GET /executions` возвращает доступные куратору выполнения. | Фильтры группы и уровня обучения появляются при наличии соответствующих данных. В сводке доступны проекты закреплённых студентов, а агрегаты по студентам и группам обозначены прочерком. |
| Блокировка аккаунта и аудит | `PATCH /users/{id}/status` принимает статус без причины. В части записей журнала отсутствует автор действия. | Подтверждение показывает, чей аккаунт изменится. В журнале отображаются полученные от API сведения. |
| Валидация и каталоги | Сервер проверяет базовый формат почты, но не требует домен `@stud.uust.ru` при регистрации студента. Серверные правила для телефона, элементов профиля, ссылок и просроченных дат отличаются от проверок форм. Список компетенций может быть пустым на чистой базе. | Проверки форм сохранены. Прямой запрос к API может пройти с данными, которые отклоняет форма. Список компетенций строится по каталогу API. |

## QA фронтенда от 10.11.2026

- В деморежиме причина блокировки сохраняется в журнале. Живой `PATCH /users/{id}/status` по-прежнему принимает только статус, поэтому поле причины в живой форме скрыто.
- Форма создания команды ограничивает название 80 символами. Текущий серверный `POST /teams` принимает до 200 Unicode-символов. Карточки поддерживают и существующие длинные названия.
- Стажировки, практики и обращения в деморежиме сохраняются в браузере. Для живой модерации действует существующий контракт из таблицы выше. В частности, блокировка закрытых программ и постоянная выдача скрытых программ доступны в деморежиме, а для живого режима требуют доработки API.
